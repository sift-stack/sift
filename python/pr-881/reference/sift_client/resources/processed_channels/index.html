    ProcessedChannelsAPIAsync ¶

    ProcessedChannelsAPIAsync(sift_client: SiftClient)

    Bases: ResourceBase

    High-level API for processed channels.

    A processed channel is a channel whose data your code writes. Each upload is a new write to one run. Reads return the run's latest complete write, and every earlier write stays readable by ID, so rerunning your code against a run replaces what readers see without losing history.

    Processed channels are experimental. The API behind them is unstable and can change without notice, and the feature must be enabled for your organization.

    Initialize the ProcessedChannelsAPI.

    upload async ¶

    upload(
    df: DataFrame,
    *,
    asset: Asset | str,
    run: Run | str,
    units: Mapping[str, str] | None = None,
    time_column: str | None = None,
    code: ProcessedChannelCode | str | None = None,
    inputs: list[ProcessedChannelInput] | None = None,
    metadata: dict[str, str | float | bool] | None = None,
    wait: bool = True,
    polling_interval_secs: float = 2,
    timeout_secs: float | None = None,
    show_progress: bool | None = None,
) -> ProcessedChannelUpload

    Write a DataFrame to a run as processed channels.

    Each column other than the time becomes one channel on the asset, named after the column, with its data type taken from the column's type. A channel is created on its first upload and reused after that. Every upload is a new write: once it completes, reads of the channel on this run return it, and earlier writes stay readable by ID.

    By default the call blocks until the data is ingested and readable. Pass wait=False to return as soon as the file is uploaded, then call wait_until_complete() on the result when you need the data.

    PARAMETER DESCRIPTION
    df

    The data. Every column other than the time is a channel. Columns must hold numbers, booleans, strings or bytes.

    TYPE: DataFrame

    asset

    The asset that owns the channels: an Asset, an asset ID or an asset name.

    TYPE: Asset | str

    run

    The run to write to: a Run or a run ID. It must belong to asset, and may be ad hoc. A write never changes an ad hoc run's bounds, and fails if any point is outside them.

    TYPE: Run | str

    units

    Units by channel name, for example {"battery_health": "pct"}.

    TYPE: Mapping[str, str] | None DEFAULT: None

    time_column

    A datetime column holding each row's time. Defaults to the DataFrame's index, which must then be a DatetimeIndex. Times without a time zone are read as UTC.

    TYPE: str | None DEFAULT: None

    code

    The code that produced the data, as a ProcessedChannelCode or a ref string. Writes made by the same code with the same channels share a fingerprint, which is how Sift tells when a run was written by older code. Defaults to the running script's path and git commit, with a hash of the script. In a notebook, pass it yourself, since there is no script to identify.

    TYPE: ProcessedChannelCode | str | None DEFAULT: None

    inputs

    The channels the code read to produce the data.

    TYPE: list[ProcessedChannelInput] | None DEFAULT: None

    metadata

    Key-value pairs that describe the write, for example its parameters.

    TYPE: dict[str, str | float | bool] | None DEFAULT: None

    wait

    Block until every write is complete or failed. Defaults to True.

    TYPE: bool DEFAULT: True

    polling_interval_secs

    Seconds between status polls while waiting.

    TYPE: float DEFAULT: 2

    timeout_secs

    Maximum seconds to wait. If None, waits indefinitely.

    TYPE: float | None DEFAULT: None

    show_progress

    Display progress during the upload and the wait. Defaults to True for sync, False for async.

    TYPE: bool | None DEFAULT: None

    RETURNS DESCRIPTION
    ProcessedChannelUpload

    The upload, with one write per channel in column order. When wait is True, every
    ProcessedChannelUpload

    write is complete.
    RAISES DESCRIPTION
    ValueError

    If the DataFrame or arguments can't be written as processed channels.
    ProcessedChannelUploadError

    If wait is True and any write failed.
    TimeoutError

    If wait is True and the writes don't finish within timeout_secs.
    ProcessedChannelRequestError

    If the server refuses the upload, for example because processed channels aren't enabled for the organization, or a channel name is already used by ingested data on the asset.

    wait_until_complete async ¶

    wait_until_complete(
    upload: ProcessedChannelUpload,
    *,
    polling_interval_secs: float = 2,
    timeout_secs: float | None = None,
    raise_on_failure: bool = True,
    show_progress: bool | None = None,
) -> ProcessedChannelUpload

    Wait until every write of an upload is complete or failed.

    A write fails when its file is rejected, its import errors, or it isn't uploaded before the server's stale threshold.

    PARAMETER DESCRIPTION
    upload

    The upload returned by upload(..., wait=False).

    TYPE: ProcessedChannelUpload

    polling_interval_secs

    Seconds between status polls.

    TYPE: float DEFAULT: 2

    timeout_secs

    Maximum seconds to wait. If None, waits indefinitely.

    TYPE: float | None DEFAULT: None

    raise_on_failure

    Raise ProcessedChannelUploadError if any write failed. Defaults to True.

    TYPE: bool DEFAULT: True

    show_progress

    Display a spinner while polling. Defaults to True for sync, False for async.

    TYPE: bool | None DEFAULT: None

    RETURNS DESCRIPTION
    ProcessedChannelUpload

    The upload, with its writes refreshed.
    RAISES DESCRIPTION
    ProcessedChannelUploadError

    If raise_on_failure is True and any write failed.
    TimeoutError

    If the writes don't finish within timeout_secs.

    warn_experimental ¶

    warn_experimental(*, stacklevel: int = 1) -> None

    Warn that processed channels are experimental, at stacklevel frames above the caller.

    The sync client runs each call on its event loop thread, where the user's code isn't on the stack, so the sync client warns when client.processed_channel is accessed instead.
