    sift_client.sift_types.processed_channel ¶

    Types for processed channels: channels whose data is written by code, one write per upload.

    Processed channels are experimental. The API behind them is unstable and can change without notice.

    CLASS DESCRIPTION
    ProcessedChannelWriteStatus

    Status of a processed channel write.
    ProcessedChannelCode

    The code that produced a write, as the caller identifies it.
    ProcessedChannelInput

    A channel the code read to produce a write.
    ProcessedChannelWrite

    One write of one processed channel's data to one run.
    ProcessedChannelUpload

    The writes created by one client.processed_channel.upload call.
    ProcessedChannelUploadError

    Raised when a processed channel upload finishes with failed writes.
    ProcessedChannelRequestError

    Raised when Sift refuses a processed channels request.

    ProcessedChannelCode pydantic-model ¶

    Bases: BaseModel

    The code that produced a write, as the caller identifies it.

    The server hashes it, with the output schema, into the write's fingerprint. Two writes with the same fingerprint ran the same code and produced the same channels.

    ATTRIBUTE DESCRIPTION
    ref

    A durable reference to the code, such as a commit and path, a package name and version, or a script URL.

    TYPE: str

    hash

    A content hash of the code at ref. Preferred over ref in the fingerprint, because two refs can name the same code.

    TYPE: str | None

    Config:

    • frozen: True

    Fields:

    • ref (str)
    • hash (str | None)

    ProcessedChannelWrite pydantic-model ¶

    Bases: BaseModel

    One write of one processed channel's data to one run.

    For each channel and run, the complete write with the highest sequence is current, and is what reads return. Older writes stay readable by ID.

    ATTRIBUTE DESCRIPTION
    id_

    The write's ID.

    TYPE: str

    channel_id

    The channel the write belongs to.

    TYPE: str

    asset_id

    The channel's asset.

    TYPE: str

    run_id

    The run the write targets.

    TYPE: str

    status

    PENDING, COMPLETE or FAILED.

    TYPE: ProcessedChannelWriteStatus

    sequence

    1-based per channel and run, in creation order. A failed write keeps its number.

    TYPE: int

    is_current

    Whether this is the write that reads of the channel on this run return.

    TYPE: bool

    fingerprint

    Server-computed digest of the code and output schema. Compare it, don't parse it.

    TYPE: str

    data_import_id

    The data import that carries the write's data.

    TYPE: str | None

    supersedes_processed_channel_write_id

    TYPE: datetime | None

    TYPE: datetime | None

    point_count

    TYPE: int | None

    ProcessedChannelRequestError ¶

    ProcessedChannelRequestError(
    response: Response,
    *,
    code: int | None,
    server_message: str,
)

    Bases: HTTPError

    Raised when Sift refuses a processed channels request.

    For example, when processed channels aren't enabled for the organization, or a channel name is already used by ingested data on the asset. Subclasses requests.HTTPError, so response holds the HTTP response.

    ATTRIBUTE DESCRIPTION
    code

    The gRPC status code of the refusal, or None if the server didn't return one.
    server_message

    The server's explanation.

    Build the error from the server's response and status.
